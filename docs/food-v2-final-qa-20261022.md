# 食養紀錄 V2.1–V2.3｜整合驗收與回滾備忘（2026-10-22）

## 發版盤點
- 完整歷史同步：分頁讀取，讀取失敗不替換本機記錄。
- 宏量營養缺值：資料庫允许 NULL，快速熱量僅填 kcal，不再補零，統計提示「僅顯示已知攝取量」。
- 食品搜尋：正式食品與候選資料區分可直接記錄／待補；候選不得假裝完成驗證。
- 食品審核：管理員身份僅於後端 food-admin Edge Function 驗證，其他帳號不可核准。
- 包裝照片：私人 storage bucket，不公開連結；提交需人工審核。
- 個人設定：常用食品、套餐及目標跨裝置保存於有 RLS 的 food_user_state。
- 健康趨勢：最近 7/30 天飲食，體重雲端保存並依帳號限制讀寫。
- 資料自主：CSV／JSON 匯出、二次確認後帳號刪除；不可將未授權刪除暴露於瀏覽器。
- 體驗：設定子頁依識別碼固定對應、食品改底部份量面板、介面百分比 90／100／110／120。
- 離線：快取殼層與本機待同步記錄，切換連線後進行重試；不快取個人 API 回應。

## 本次加強
1. 修正 Service Worker 離線資產故障：缺少 JS/CSS 不會再收到誤導性的 HTML，而回傳明確 503；頁面導覽仍可返回已快取首頁。
2. 完整雲端記錄替換本機時，對雲端不存在、未在待同步佇列且未在待刪佇列的舊紀錄另外隔離保存於 `S.localRecovery`。避免把可能是跨裝置刪除的資料自動重傳，但使用者可以先匯出備份。
3. JSON 全備份加入 `recovered_local_only_logs`，不默默捨棄遺留的本機舊記錄。
4. 增加實際用 Node VM 模擬 Service Worker 離線路由的自動測試。

## 已知限制／注意
- GitHub Actions 可測語法、DB 契約、離線 SW 行為與無頭 Chromium 的介面幾何，但不等於 iPhone 實機掃碼、真實 Supabase 登入及推播到達。
- 食品營養候選仍有缺欄，不能在尚未取得官方包裝標示前推算填滿。
- 自動跨裝置合併偏好設定遇離線雙端衝突需特別測，必要時改成版本比對及明確選擇，不應無提示覆蓋。
- 舊版孤兒記錄可在「帳號設定 → 完整 JSON 備份」取得，暫不自動恢復，防止重複記帳。
- 刪除帳號是不可逆操作，勿使用正式帳號測試。
- Supabase 安全顧問提示須另外評估 pg_net extension schema 與登入洩漏密碼保護，無重大資料外洩事件證據。
