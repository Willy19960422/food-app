# 食養紀錄｜全介面視覺優化與 QA 清單（2026-10-22）

## 修改目標
正式 iPhone PWA 截圖顯示：食品份量 modal 右上角「關閉」按鈕與主操作一樣大，佔掉整列；資訊與表單偏大，各子功能由獨立模組注入字體/間距/按鈕 CSS，視覺語言不一致。此次**統一視覺，不重寫資料計算及儲存**。

### 共用 UI 規範
- 主色、深淺色原封不動使用既有 `--brand / --bg / --card / --ink / --mute / --line`，避免色彩與可讀性回歸。
- 一般文字 14px；頁首標題 20px；卡片標題 16px；次要說明 12px。
- Input/select/textarea 16px、最小高度 44px（避免 iOS Safari 聚焦時強制放大），全部保留焦點外框。
- 主按鈕最小 44px，圓角 11px；次按鈕淡線框、未選狀態不再與主按鈕爭奪視覺焦點。
- 卡片圓角 16px、間距 11px、padding 14px、極淡陰影；各畫面使用相同的字重、背景及邊框。
- modal 右上只顯示小 `×`，視覺 40×40px 可觸控區（小 X 符號本身更小）；標題與 X 同列；完整 aria-label、焦點控制、ESC／背景點擊取消。
- 底部固定導覽保留「今日／紀錄／設定」三項功能，字級 14px，強調線縮小、保留安全區及原本 active class。
- 介面原有 90/100/110/120% 縮放、系統／淺色／深色選擇保留；重視 120% 長字、輸入框不超出。

## BUG 根因與保護措施
1. **關閉按鈕過大**：先前 `food-sheet.js` 在 `selectedFoodInfo` 最前面插入寬度自動、包含「關閉」文字的 `ghost` button。現在移到標題右側的 header，改成 `×`，保留 `aria-label` 和 40px 觸控區。
2. **每個模組各自注入 CSS**：沿用原 JS 與事件，但增加單獨 `ui-polish.css` 的共用樣式層，避免複製或修改十幾處營養/資料程式。
3. **編輯飲食視窗操作不一致**：原編輯 modal 只有底部取消按鈕，沒有右上 X。新增純 UI 控制器 `ui-polish.js`，小 X **呼叫原有取消按鈕**，不建立另一套儲存/刪除處理器。
4. **手機版快取未刷新**：`index.html` CSS/JS 加版本，`sw.js` 提升快取名稱並預先快取兩個新增檔案，避免離線頁面拿不到資源。
5. **不應觸及資料**：此次沒有 Supabase schema、SQL、RLS、營養數值、登入、推播 API、掃碼或歷史紀錄操作。

## iPhone PWA 實機需確認
- 先重開 PWA，不先清除 Safari 網站資料以免誤清離線待同步紀錄。
- 在「夜市小吃 → 全部品項 → 台式鹹酥雞」點選，右上應是小 `×`，不再是大「關閉」；確認份量 1 份與實際加入一致。
- 從食品選單、拍照／手動條碼進入各表單，不應出現橫向捲軸、按鈕重疊、灰色區塊文字看不清。
- 設定四個子頁、通知開關、推播測試、每日目標及外觀設定仍可使用。
- 測試 90%、100%、110%、120%；深/淺色；有鍵盤展開時 modal 應可以捲動與關閉。
- 原有飲食紀錄、體重及匯出資料須核對；不要用正式帳號測試永久刪除。
