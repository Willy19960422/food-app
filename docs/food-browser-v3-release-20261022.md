# 食養紀錄食品瀏覽 V3｜逐層方格版發佈與驗收

日期：2026-10-22

## 修改目標
取代「超長的食品清單＋全部商品一次往下滑」。
- 分類（2 欄）→ 品牌（2 欄）→ 食品種類（3 欄）→ 商品（2 欄）。
- 商品每頁 12 筆，明確上一頁與下一頁，不再把下一批 20 筆直接累積在長清單下方。
- 任何層級都保留搜尋框；清除搜尋後回到原本分類路徑。
- 「最近吃過」「我的常用」提供快速選取。
- 直接點選整張商品卡片。完整且符合官方快選條件的食品繼續使用既有份量底部視窗；營養未完整或未核可的候選食品仍需進行手動核對，不直接記錄為已驗證食品。
- 雙欄商品卡片各自顯示品名、資料品質、熱量、P／F／C。未知營養顯示「—」，永遠不自動填 0。
- 不新增 icon，不額外堆疊多個 modal。分類切換在同一頁完成。

## 相容性
- 原有主分類選單、品牌按鈕、商品渲染程式仍留在 index.html，若 V3 JS 無法載入，會使用舊版作為安全備援。
- 資料來源沿用 getCombinedFoodList、food_catalog_candidates、S.log、S.customFavorites。
- 不新增或修改 Supabase 資料表、RLS、營養數值、歷史飲食紀錄。
- 仍使用原本 selectFoodItem、food-sheet.js、prefillOfficialFood、canQuickRecordOfficial 等 API，不重寫營養換算或 AI 功能。
- PWA Service Worker 新增 food-browser-v3.js 預先快取並提升 cache 版本，幫助手機取得新檔案。
- 舊資料中的肯德基、麥當勞等可能被匯入成「外食餐飲」，畫面分類時依品牌對應回「連鎖餐飲」，不批次改動資料。

## 自動驗收
- 新 Node 契約測試：tests/food-browser-v3.test.cjs
- 新真 Chromium 測試：tests/food-browser-v3.browser.test.cjs
  - 實際點擊超商→7-ELEVEN→微波餐盒，顯示 12 筆雙欄卡片
  - 第 1／3 頁切換至第 2 頁
  - 全域搜尋全家未完整標示品項，點擊會送至補件，不會把缺值當成 0
  - 清除搜尋返回原本分類、逐層返回、最近與我的常用可選
  - 舊資料肯德基可以在連鎖餐飲分類找到
  - 寬度、卡片無重疊、無水平捲軸，在 90%、100%、110%、120% 測試
- 保留既有掃碼、分類、離線、通知／設定、食品卡片、完整 V2 等 GitHub Actions 回歸測試。

## iPhone 實機測試（仍需使用者驗收）
1. 完全關閉再開啟 PWA，確認新方格版載入（不要清除網站資料以免離線資料遺失）。
2. 從超商→全家→微波餐盒選取商品，再一路返回，確認沒有畫面堆疊。
3. 從「最近吃過」「我的常用」直接進入商品。
4. 測試搜尋品名、品牌、已收錄食品條碼；清空查詢應回到原分類。
5. 12 筆分頁、食用品項底部份量確認視窗、已核准與未核准商品的處理。
6. 90～120% 介面顯示，以及極窄 iPhone 畫面的文字換行。
7. 測試日誌、掃碼、通知、離線、P/F/C 缺值行為不回歸。

## 回退與風險
- GitHub Pages 版面異常：Revert V3 PR 合併提交並更新 Service Worker。
- V3 JavaScript 單一載入失敗時，會回到舊版分類 UI，不會影響資料庫。
- 舊資料部分商品名稱可能不易以正規表示式分辨類型，尚無明確對應會歸「其他鮮食」；人工整理商品類型可以在下次單獨改進。
- 真 iPhone 鏡頭、Safari 安裝模式、真實登入與網路環境不等同無頭 Chromium 測試，不能稱作已實機驗收。
